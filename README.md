# Browser Runtime Formal Model

Lean 4 executable specification for a stateful CDP browser driver/runtime.

The model separates these concerns:

- **Runtime graph**: ownership/topology (`Browser -> Context -> Page -> Frame`).
- **State machines**: mutable page/runtime/input/action state.
- **Event scope**: page, browser-context, or browser.
- **Policy + commands**: the only legal route for cross-page reactions.
- **Proofs + executable replay**: static safety theorems and concrete trace checking.

## Proven properties

The model proves that:

1. A page-local event cannot mutate a sibling page.
2. Human input while automation owns a page enters `conflict` and suspends the action.
3. Destroying an execution context makes continued primitive execution impossible.
4. Closing a page makes continued primitive execution impossible.
5. Browser disconnect makes primitive execution impossible on every page.
6. A `PageCommand` cannot mutate a non-target page.
7. Context unavailability blocks execution for every page in that context.
8. Every policy command generated by `contextUnavailable C` targets only pages in `C`.
9. Applying a command list cannot change a page when no command targets that page.
10. Reacting to a Context-A event cannot mutate page state in a different Context-B.

These are properties of the abstract driver model. They do **not** by themselves prove a future C/C++ CDP driver implementation correct. The conformance layer is trace based: the driver emits normalized events/actions, and CI replays them through this executable model.

## Reactive pipeline

```text
CDP / injected observer
        |
        v
 normalized RuntimeEvent
        |
        v
       step              -- local/parent state observation only
        |
        v
 Policy.commandsFor      -- explicit response decision
        |
        v
   PageCommand[]
        |
        v
    applyCommands
        |
        v
      react
        |
        +--> Runtime state
        +--> telemetry/event journal
        +--> ActionSM / BehaviorTree consumers
```

A page-local event has no policy commands by default. Context events may generate commands only for pages in that context. Browser events may generate commands for all known descendant pages.

## Build

```bash
lake build --wfail
lake exe browser-runtime-check
```

The project is pinned to Lean 4.33.0. GitHub Actions builds the complete model with `--wfail` and then runs the executable trace scenario. The executable now checks every intermediate `react` state with `traceSafe`, including Context and Browser parent-state changes.

## Driver integration target

The C/C++ driver should normalize raw CDP/injected events into `RuntimeEvent` before any runtime state mutation. Cross-page effects must be materialized as explicit policy commands; direct sibling-state mutation has no representation in the proven model and should therefore fail conformance replay.
