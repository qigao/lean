# R2.M5a — Source-owned key-person passage authority

Tracked by Issue #120. Parent Draft PR #119. This is a finite executable
resource-control mechanism, not a new universal theorem or social power score.

## Scientific foundation

- Emerson, Power-Dependence Relations (1962): asymmetrical dependence on a
  valued resource is distinct from nominal rank or prestige.
  https://web.mit.edu/curhan/www/docs/Articles/15341_Readings/Power/Emerson_1962_Power-dependence_relations.pdf
- Borgatti, Identifying sets of key players in a social network (2006):
  structural key-player selection depends on whether the goal is diffusion
  or fragmentation, so raw centrality is not a universal power measure.
  https://doi.org/10.1007/s10588-006-7084-x
- Granovetter, Threshold Models of Collective Behavior (1978): behavioral
  response depends on individual thresholds; one centrality or rank value
  cannot determine adoption or an event outcome.
  https://doi.org/10.1086/226707

These are existing external results. This PR only operationalizes a tiny,
explicit part of resource decision authority through the original V19 engine.

## Runtime semantics

The source-authoritative PassageSpec now accepts an immutable,
exactly validated tuple of controller_agent_ids. Only a nonempty set
restricts its OPEN_PASSAGE and CLOSE_PASSAGE intents. Empty means
unrestricted (the original V19 interpretation) and is deliberately omitted
from to_dict to keep historical model hashes and reviewed legacy vectors
byte-for-byte identical. A restricted policy changes its world model hash.

The original resolve_situated_round checks source location first, then
authorization. An unauthorized co-located Agent receives a real rejected
event with outcome not_authorized; it cannot change the source passage
state and cannot turn into a passage_conflict that vetoes a permitted
contender. Role strings, degree, trust and prestige never grant authority.

## Same-model native controlled observation

One restricted immutable V19 model places explicit controller Alice,
whose descriptive role is analyst, at records. Manager Dana is also
co-located but is NOT a controller. Bob and Carol are in the open office.
Passage records-open begins closed. Three original-world action sequences
start from this identical world and execute the same subsequent Alice MOVE
and TELL intents.

- control_wait: Alice WAIT, then MOVE fails passage_closed; Bob only DETECTS
  the later source-owned TELL.
- authorized_open: Alice OPEN succeeds, then MOVE succeeds; Bob's actual
  later TELL percept is EXACT.
- unauthorized_manager_open: Dana tries OPEN in the same physical room
  but is refused not_authorized; subsequent MOVE and TELL match a closed gate.

Two independent same-engine checks demonstrate that Dana's rejected OPEN
cannot veto simultaneous authorized Alice OPEN and Dana's rejected CLOSE
cannot mutate a currently open passage.

The observer stores source model and world hashes, story/round hashes,
event hashes, success/outcome, final gate status and Bob percept fidelity.
It does not publish the message body, synthesize cognition/trust/centrality,
or interpret branched event IDs without story identity. Only one source
world model owns passage rules.

## Admission limits

This verifies deterministic software behavior under explicit world rules;
it does not identify a real person's power, prove a societal law,
authenticate external actors or estimate a population causal effect.
sample_size_per_arm=1, causal_attribution=UNATTRIBUTED,
confidence_interval=NOT_ESTIMABLE, external_validation=NO_EXTERNAL_VALIDATION.

M5b: selected-relation V24 structural bridge/reach descriptors, separate
from permission. M5c: source-owned V19 EXACT/TELL/INSPECT testimony and
directed trust, separate from permission and structural centrality.
M5d: external population data, matched seeds, confidence and causal study.
Do not build a second graph engine or infer global key-player scores.

Retain the same original Python, 35+11 Lean trust/BB/PathN and
World Studio/Playwright gates. One reviewed native source vector is
regenerated byte-for-byte in the existing workflow. No extra workflow
file, installer or consumer project.
