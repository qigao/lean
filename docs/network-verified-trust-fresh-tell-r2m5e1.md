# R2.M5e.1 — Verified source trust before a genuinely new native TELL

Tracker: Issue #120. Stack on Draft #125 (M5e.0), which introduces
the source-owned opt-in direct EXACT TELL weighting. This document is
a preregistered deterministic V19 acceptance case, not a statement of
universal social causality.

## Research question and scientific firewall

Can the existing V19/SQLite Agent cognitive and social-memory owners
perform a **true confirmation vs contradiction trust update**, then
emit a **new later TELL** and admit it with the learned trust in a real
native decision?

This is distinct from:
- a generic six-hop result (already known),
- M5a world-resource permission,
- M5b selected-directed structural reach and removal sensitivity,
- M5c claim/trust response to private verification,
- M5d source action negative result,
- M5e.0 initial configured social trust protocol sensitivity.

Because earlier confirmed and contradicted message **content** changes,
the two branches' epistemic history and posterior cognitive state can
also differ. The result must always carry
historical_context_match=NOT_MATCHED_PRIVATE_EVIDENCE_OR_BELIEF and
trust_only_causal_effect=NOT_IDENTIFIED. Even a different actual
MAP-selected action would be *model-local combined-history behavior*,
not proof the trust delta alone caused a real-world social event.

## One original V19 world, one historical content contrast

An identical V19 source model with Alice as declared controller of
the closed records-open passage, Bob initially at open, Carol at lobby
and Dana at manager. The original social policy enables M5e.0 direct
trust weighting. A single cognitive model shared by both branches
explicitly permits Alice to repeat a TELL (using original V19
SituatedActionSpec.repeatable), not a new planner.

Seven authored **source world actions** in both branches:

1. Alice INSPECT memo in records (actual verification source).
2. Alice opens her controlled records-open passage.
3. Alice moves to open.
4. Alice TELL one of two source contents:
   - confirmed-history: "The restructuring is approved."
   - contradicted-history: "The restructuring is denied."
   It cites the real preceding INSPECT event ID. This is the ONLY
   intervention in the authored schedules.
5. Bob moves from open to records.
6. Bob privately INSPECTs the real memo (which says approved).
7. Bob returns to open, restoring identical current physical
   positions and gate state in both histories.

The original V19 private percept memory and social evidence owners
are now initialized at the complete Story checkpoint (round 7).
Earlier percepts are historical **SQLite recall** eligible, not
re-introduced as new direct signals. This is intentional.

## Strict native clock and provenance

- **Round 8:** original source V19 cognitive/social transition
  recalls one eligible Bob EXACT testimony and one own private
  INSPECT verification. The original social owner must learn
  confirmed trust 0.5→0.6 or contradicted trust 0.5→0.3.
  Alice's original planner may also emit a TELL in this round,
  but that event is not yet a post-revision emission because
  social learning occurs later in the same synchronous round.
- **Round 9:** starting from round-8 learned trust, original
  V19 planner must emit a NEW Alice TELL. Its source_event_ids
  must reference an actual previously observed eligible source
  event in the same Story (the round-8 original native TELL),
  not a synthetic hash. Bob must receive a new EXACT native
  percept using actual pre-round spatial locations.
- **Round 10:** native V19 cognitive/social engine processes
  the actual new round-9 TELL using Bob's current learned
  directed source trust. Its direct
  SituatedBeliefAdmission.source_trust must be 0.6 vs 0.3,
  and that exact percept ID must appear in Bob's original
  SituatedCognitiveDecision. The original world engine must
  emit the selected action's actual success/outcome.

The same SQLite database is used for all three native rounds
within each arm; each branch uses an independent database.
World/Story, cognitive and social hashes remain provenance
qualified. Same action/event IDs across diverging Stories are
not presumed to be the same historical event.

## Admission and negative tests

Require one real successful authored action in each of seven
rounds, exactly one history-change input, identical current
physical positions and gate status, source-hash-bound Bob EXACT
earlier and later TELL percepts, valid 0.6/0.3 original learned
trust, one legitimate previous testimony + private verification,
and an exact new round-9 TELL actually consumed in round 10.

Do not hand-edit a social trust field, create a message from a
projection or infer a world action from a threshold. Native
world event success/failure must be taken from the original
resolver. Redacted JSON contains no TELL text or private
INSPECT evidence contents; source hashes and typed aggregate
status suffice for the reproducible acceptance.

One source-generated JSON vector is printed in CI for review
exactly once and pinned immutable. Existing V24 focused Python
and independent Lean source-conformance lanes must compare
the exact bytes. Full Python/35+11 Lean theorem trust/BB/PathN
and Studio/Playwright remain mandatory, with cached bounded
singleflight runner use. No new CI workflow, installer/consumer,
fallback graph, independent simulator, or six-hop theorem.

Scientific labels remain:
- source_story_lineage=DIVERGENT_HISTORICAL_STORIES
- sample_size_per_arm=1
- trust_only_causal_effect=NOT_IDENTIFIED
- historical_context_match=NOT_MATCHED_PRIVATE_EVIDENCE_OR_BELIEF
- confidence_interval=NOT_ESTIMABLE
- external_validation=NO_EXTERNAL_VALIDATION
- cross_mechanism_ranking=FORBIDDEN

A later empirical/causal study must explicitly match eligible
real-world opportunity, pre-treatment social/cognitive history,
external observation/data and independent sampling before any
uncertainty or generalized effect claim.
